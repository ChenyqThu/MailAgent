桌面 App 只能在你那台 Mac 上用。远程网页版让你离开 Mac 时，也能用浏览器看邮件、搜索、处理今日待办——邮件数据不会被复制到云端，浏览器里看到的内容，是从你自己那台一直开着的电脑实时取来的。

## 跟桌面版的差别

远程网页版走网络，瓶颈在传输，所以有些操作比本机慢，也有意做了减法：

| 能力 | 桌面（本机） | 远程网页版 |
|---|---|---|
| 邮件列表 / 详情 / 搜索 | 秒开 | 稍慢，可用 |
| 标记、归档、重传 | 即时 | 略慢，正常可用 |
| 下载大附件 | 秒开 | 流式下载，大文件会慢 |
| 今日、报告、AI 对话 | 有 | 有 |
| 资料库 | 有 | **不提供**——依赖本机文件系统与语义检索服务 |
| 群聊 | 可发起 | **只读浏览**——建群、发言需要本机的 AI 服务 |
| 命令面板、批量长任务 | 有 | 没有，留给本机操作 |

简单说：远程用来看和轻量处理，重活留给坐在 Mac 前时做。

:::caution[Mac 必须保持开机联网]
远程访问的数据源就是你那台 Mac。它睡眠、关机或断网时，远程就看不到最新内容。
:::

## 自己搭一个

远程网页版不是开箱即用的功能——它需要你自己起一个本机 API 服务，再用某种方式把它安全地暴露出去。大致三步：

1. **起本机 API**

   ```bash
   mailagent serve-api   # 默认监听 127.0.0.1:8200，只对本机开放
   ```

2. **建一条反向隧道**，把这个本机端口映射到一个公网地址（例如 `https://<your-domain>`）。常见做法是用 Cloudflare Tunnel 之类的服务——好处是你的 Mac 不需要公网 IP，也不用在路由器上开端口转发。

3. **加一层访问控制**，只放行你自己。推荐在隧道前挂一道登录（例如按邮箱白名单的 SSO 网关），公网上的陌生访问会被挡在登录页之外，进不到 MailAgent 本身。

登录成功后，用任意浏览器打开你的地址，看到的就是同一套界面。iOS / iPadOS 上用 Safari 打开、登录后从分享菜单选「添加到主屏幕」，可以当成一个全屏 App 使用。

:::note[这部分需要一点运维经验]
反向隧道与访问控制的具体搭建步骤因人而异（用什么隧道服务、怎么配登录），不在这篇文档展开，完整的部署手册见下方链接。
:::

## 安全要点

- 全程 HTTPS 加密。
- 邮件、附件都在你的 Mac 上，云端不存任何邮件内容；只有你主动配置的模型服务，会收到 AI 处理时用到的那部分内容。
- 写操作（标记、重传等）用到的密钥只在你 Mac 的后端使用，不会进入浏览器。

## 常见疑问

- **打不开 / 一直转圈？** 先确认 Mac 开着且联网，本机 API 服务和隧道都在跑。
- **登录被拒？** 确认用的是你在访问控制里放行的那个账号。
- **手机上看着不像 App？** 用 Safari 打开后走「添加到主屏幕」，从主屏图标启动才是全屏体验。
