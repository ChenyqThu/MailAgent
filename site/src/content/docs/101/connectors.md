MailAgent 的 AI 助手可以直接读写你在用的其他服务——搜索 Notion 页面、更新 Jira 议题、读 GitHub 上的代码。这条能力走的是 MCP（Model Context Protocol），我们把它叫做「外部连接」。

## 目录：两条轨道

外部连接目前收录 16 家服务，分两条轨道：

- **直连**——Notion、Atlassian（Jira + Confluence）。MailAgent 直接连接它们的官方端点，不经过第三方。
- **Composio 托管**——其余 14 家：Asana、Figma、GitHub、Gmail（邮箱）、Google 日历、Google 云端硬盘、Intercom、Linear、Outlook（日历与联系人）、PayPal、Sentry、Slack、Stripe、X（Twitter）。这些服务经由 Composio 的云代管接入，需要你自己的 Composio API key。

:::caution[Composio 托管的数据路径]
经 Composio 托管的连接，工具调用的入参与返回结果都会经过 Composio 的服务器，授权令牌也存在那边，不在你的电脑上。Composio 默认会保存调用日志（含内容）最长一年——如果介意，去 Composio 后台的「Settings → General」把日志存储关掉。Notion 与 Atlassian 走直连，没有这层中转。
:::

Composio 有免费档，每月 20,000 次调用，个人使用通常够用。在 [app.composio.dev](https://app.composio.dev) 注册账号，在「Settings → API Keys」生成一个 key，粘贴进 MailAgent 即可使用目录里的其余 14 家服务。

## 怎么连接

外部连接有自己的独立页面：导航栏里的「Connectors」，也可以从 设置 → 连接器 跳转过去。

1. 在目录里找到要连的服务，点「连接」。
2. 浏览器打开该服务的授权页面，登录并同意后自动跳回。
3. 连接成功后，MailAgent 会同步一次这个服务当前提供哪些工具。

授权令牌加密保存在本机；到期前会自动刷新，刷新失败时状态会变成「授权已失效」，重新走一次上面的流程即可。

:::caution[远程网页版不能连接]
连接的授权回调会跳转回本机地址，只能在桌面 App 里完成；远程网页版打不开这个流程。
:::

## 逐工具审批档

同一个连接下的每个工具，都能单独设三档：

- **自动**——AI 调用时直接执行，不弹卡。
- **需审批**——每次调用前弹出确认卡。
- **禁用**——这个工具对 AI 不可见。

新连接的工具默认是「自动」，包括写入与更新类。服务方标记为「破坏性」（可能覆盖或删除数据）的工具，若你把它设为「自动」，会先弹一次一次性的红色确认。也可以按只读 / 写入 / 更新分组批量设置，或一键重置回默认。

远端服务偶尔会下线某个工具——这时它会标「已失效」，配置保留但不再对 AI 可用；攒多了可以一键清理。

:::note[跟内置工具是同一套逻辑，不同一个位置]
邮件、日历这类内置工具的审批档在《权限与审批》里讲过（见下方链接），外部连接的工具用的是同一套三档语义，只是单独放在 Connectors 页管理。
:::

## 自定义 Agent 与报告 Agent 怎么用连接

自定义 Agent 与报告 Agent 各有一张「外部服务」能力卡，按连接（而不是单个工具）设三档：**关 / 只读 / 可写**。无人值守运行时，Agent 只能用你授权范围内的工具，超出范围的调用不会发生。

邮件预处理分类是特例：它默认关闭外部连接，且没有审批链可以弹卡，所以打开后只有档位为「自动」的工具会被它用到——设成「需审批」在这个场景里等同禁用。

## 连接健康与重新授权

Connectors 页的每条连接都能看到：授权范围、令牌有效期、上次同步工具清单的时间，以及最近一次错误。授权失效时会提示「重新连接」，走一遍浏览器授权即可，不用先手动断开。断开连接可以只删凭证（工具档位保留，重连后继续生效），也可以连同配置一起清除。

## 目前在实验室

外部连接默认关闭，在 设置 → 实验室 里打开，开启后需要重启后端与应用各一次才会生效。

## 常见疑问

- **一定要用 Composio 吗？** 只有 Notion、Atlassian 之外的 14 家才需要；Notion 和 Atlassian 是直连，不用注册 Composio。
- **AI 会不会自己乱调用外部服务？** 写入 / 更新类工具默认可以自动执行；不放心的话把它调成「需审批」，之后每次调用都要你点头。
- **数据会不会被外部服务看到？** 只有你连接并放行的服务，才会收到 AI 处理它时用到的那部分内容；未连接的服务完全不涉及。
