AI Chat 是你和一位 Agent 的对话；群聊是另一个一级域——同一个群里可以有好几位 Agent，各自按设定的响应方式参与。适合需要几个角色接力、彼此看得见对方发言的场景；单纯问一件事，用 [AI 对话](/101/ai-chat/) 更直接。

## 建一个群

点「新建群聊」，填群名、选成员（有人数上限）、可选的用途说明（一句话，会注入每位成员的身份提示）、响应模式，以及可选的主持人。

## 谁会回、什么时候回

每位成员有自己的响应模式：

- **实时**——群里来了别人的消息就可能主动回；
- **点名**——只有被 `@` 到才回，这是默认模式。

主 Agent 也可以入群：入群之后它只作为普通成员发言，不带单聊里的那一套工具。群里最多设一位主持人，主持人可以在这个群和它建的子群之间投递消息，也可以不设。

## 编排过程可见

发消息之后，界面上能看到谁在发言、谁在排队、谁这一轮选择沉默。跳过、重复内容被折叠、失败，每种情况都标出原因，不会假装什么都没发生。任何时候可以点「停止本轮」，界面会显示为什么停下来——链路到了上限、单个成员发言次数用满、成员之间开始重复绕圈、超出预算、你自己点了停止，等等。

## 话题

群里的消息可以开一个「话题」——一个带独立参与者名单的子讨论，可以单独停止而不影响父群主线；话题的开销计入父群的预算窗口，未读和通知都能直达对应话题。话题只能开在顶层群，子群内不能再开话题。

## 预算与用量

每个群有一套自己的上限：一条对话链最多唤醒多少次、每小时最多发言多少次、每小时 token 与费用上限、群内累计发言上限。群详情页能看到最近一段时间的用量与近期的唤醒记录，超限时上一次停止的原因也会显示在这里。

## Agent 的群工具与审批

Agent 在群里有专属工具——读群历史、看成员、群内发言、建群和建子群。建群和往群里投递消息都需要你确认，不因为在群聊场景就绕开审批。

## 事项跟进也能进群

开启群聊后，可以把「事项跟进」拉进某个群；它在群里发言时用的是那件事项配置好的全局跟进模型，详见[事项](/101/matters/)。

## Labs 状态

群聊多 Agent 目前在实验室（Labs），出厂默认开启，可以在「设置 → 实验室」里关掉。

## 只在桌面端可用

群聊需要本机运行的 AI 服务；远程网页版只能只读浏览群里的消息记录，不能发言，也建不了群。

## 常见问题

- **群里发消息没人理？** 检查是不是只 `@` 了发言者自己，或者既没有实时成员、也没有 `@` 任何人——这两种情况都不会唤醒任何人。
- **能撤销刚才的停止吗？** 停止不可撤销，发一条新消息即可继续这个群的讨论。
- **删除群会怎样？** 群里全部消息一起删除，不可恢复；已经存在的子群会保留，但不能再从这里跳回父群。
