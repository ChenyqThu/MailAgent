邮件只是线索，事情本身才是你要推进的东西。「事项」把一件事从散落在收件箱、日历、聊天记录里的碎片，整理成一个有背景、有目标、有进展的对象——需要跟进时，你打开这一个页面就够了。

适合用来管这类事：需要多轮邮件往来才能推进的合作、要跟到底的采购或合同、涉及多个人的项目节点。一次性的小事，直接在邮件里处理会更快。

## 第一次使用

点左侧导航的「事项」进入工作台，不需要单独开启。

- **新建**：点「新建事项」，填标题、类型（可以自定义类型）、优先级，以及**背景**（这件事怎么来的、有哪些约束）与**目标**（做完时什么成立）两个独立输入框。
- **从邮件创建**：在邮件详情页可以直接「从邮件创建事项」，把当前邮件或整条会话变成事项的第一份关联资料。
- **调研并预填**：从邮件创建时可以点「调研并预填」，Agent 会读这条会话、检索相关邮件与已连接的文档，给出一份标题、描述、建议干系人与建议资源——这份建议可以再改，**不会自动创建或写入**任何东西。
- 保存前如果检测到可能已有类似的事项，会提示你核对，只提示不阻止。

## 日常操作

清单页有「事项」与「看板」两个视图，四个范围可切换：进行中、已完成、已归档、回收站（默认显示全部）。筛选、分组、排序在同一个菜单里完成，可以叠加关注中、等待、7 天内到期、高优先级（P0-P1）、有待审提案、缺下一步这些快捷条件；也可以按状态、到期、优先级或标签分组。标签由形状与颜色两个维度组成，方便区分。

详情页分四个标签：

| 标签 | 看什么 |
|---|---|
| **状态** | 当前状态摘要（标注更新时间与来源）、背景与目标、完成标志清单 |
| **上下文** | 干系人、关联资料 |
| **进展** | 这件事的脉络——按时间叙述，不是逐条改动记录 |
| **运行** | 跟进 Agent 每一轮的执行记录 |

- **完成标志**：给这件事定几条可判定的标准，比如「合同双方已签署」；勾满会提示可以推进到「已完成」，但状态永远由你手动改，不会自动跳转。
- **行动项**：六种类型——行动项、里程碑、决策、阻塞、待解问题、备注；六种状态——待开始、进行中、等待中、受阻、已完成、已取消。支持行内编辑。
- **干系人**：从通讯录里选人，标注角色（决策人 / 审批人 / 执行人 / 被通知 / 外部相关 / 其他），可以拖到「核心干系人」组置顶；勾选「正在等他」会在事项上产生一条等待信号，超过约定时间会进入需关注队列。通讯录里没有的人可以直接用邮箱建入。
- **关联资料**：支持邮件与会话、外部链接、本事项附件、资料库文件、日历事件五类。每份资料可以设内容可见性——完整、仅元数据、排除；网页类资料会记录版本轨迹，检出新版本时保留历史与变化说明。
- **导出**：单个事项可以导出为 JSON（给程序读）或 Markdown（给人读）。资料只导出引用与地址，不导出正文——邮件、文档本身仍是内容的权威来源。

:::note[进展和操作日志不是一回事]
「进展」是你和 Agent 一起维护的叙事——这件事走到哪了、下一步是什么。「操作日志」是只追加不可改的审计记录，谁在什么时候动了哪个字段，用来回看和追责，不参与日常阅读。两者在详情页是分开的标签。
:::

## 让 Agent 参与

新建事项默认就带一条跟进规则——每 3 天检查一次（上午 9 点），你可以随时改。触发方式四选一，可以并存：

| 触发方式 | 什么时候跑 |
|---|---|
| 定时 | 按固定节奏 |
| 事件驱动 | 关联了新的邮件或会话、关联文档有新版本、关联的会议结束 |
| 条件 | 出现「有开放项已过期」「健康度变为有风险」「等待某人超过 7 天」这类信号 |
| 手动 | 只在你要求时跑一轮 |

跟进 Agent **只读不写**：它检索邮件、会话与已连接的外部服务（比如 Notion、Jira），把发现的新证据整理成「提案」——更新状态摘要、加行动项、补资料、补干系人、记一条进展，逐条列出等你接受或拒绝。它自己一个字都写不进事项。

每条提案会标出属于哪一类，帮你判断该不该接受：

- **事实**——有邮件或文档来源支撑，可以直接采纳；
- **推断**——是 Agent 自己的解读，需要你判断；
- **字段变更 / 行动项 / 关联资料 / 记进展**——分别对应会改写正式状态、新增或修改行动项、正式关联一份资料、在进展里留一条记录。

需关注的信号有七类：等待逾期、行动逾期、临近截止（7 天内，含已逾期）、健康下降、需要审阅、跟进失败、上下文缺口。每条信号可以解决、稍后三天提醒、或忽略——已经解决的信号，在判据没有重新成立之前不会再打扰你。

行动项也可以直接**派给 Agent 执行**：派发后有自己的执行状态（排队中、执行中、等你回答、已交提案、已完成、失败、已取消）。如果它缺一条关键信息，会停下来问你，而不是自己接着编——回答之后才会起新一轮。

模型、思考强度、备用模型、上网能力（保持完整 / 仅搜索 / 关闭）可以在全局或单个事项上分别配置，全局配置在「设置 → 事项」，也可以从事项详情打开。

点右下角主 Agent 头像可以直接就这个事项开始对话，会自动带上当前状态、开放行动项数量、干系人数量、置顶资料摘要作为上下文；改动仍会以审批卡的形式等你确认，不会绕过审阅流程。

:::tip[事项跟进也能进群聊]
在设置了 Labs 群聊后，可以把「事项跟进」拉进一个群，用这个事项配置好的全局跟进模型参与讨论。
:::

## 限制与常见问题

- **默认跟进规则只对新建事项生效**：升级后老事项不会被自动补上，需要的话去详情页手动配置。
- **干系人的姓名、组织信息来自通讯录**：改名、合并在通讯录里做，会同步更新到 TA 出现的所有事项；事项里只保存角色与备注这类只属于本事项的信息。
- **关联资料不导出正文**：无论是查看、导出还是提案里的引用，资料库、邮件、外部文档本身才是内容的最终来源。
- 被你拒绝过的资料或合并建议，在没有实质新证据前不会重复出现。
