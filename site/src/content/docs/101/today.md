MailAgent 每天做的大部分事——分类邮件、跟进事项、生成报告——都不需要你在场。「今日」把其中真正需要你过问的部分收在一页：打开应用，看这一页就够了。

## 五节

打开应用默认落在今日页；左侧图标导轨也能随时点回来。页面按五节组织，从上到下：

| 节 | 收的是什么 |
|---|---|
| 等你拍板 | 需要你批准、修改或拒绝的审批——Agent 想执行的写操作、跟进 Agent 提出的事项更新提案、派给 Agent 的行动项抛回来的问题 |
| 今天的会 | 今天日历上的日程，按开始时间排列，标出还有多久开始 |
| 待回邮件 | 判定为「需要回复」但还没回的邮件，按线程聚合 |
| 临期事项 | 7 天内到期（含已逾期）的事项 |
| 智能体产出 | Agent 最近交出的成果——生成完毕的报告、跟进提案、行动项的执行结果 |

一条都没有时，页面会明确写「今天没有需要你的事」，不会让你怀疑是不是加载失败。

## 拍板：三种回应方式

每张审批卡代表 Agent 想做的一件具体的事——发一封邮件、改一条事项、执行一个工具。你有三种回应：

- **允许**：按卡片上写的内容照办。
- **改了再执行**：大多数卡片可以在批准前编辑参数或正文，改完点「允许」，就按你改过的内容执行。
- **拒绝**：可以留一句拒绝理由（可选）。这句话会连同「拒绝」一起交回给 Agent——它因此知道这次为什么不行，而不是只看到「被拒绝」三个字，下一次也更可能提对方案。

卡片上写的收件人、主题、改动这些内容，由服务端按真实要执行的操作生成，不是转述 Agent 自己的说法；批准之后就会照此真实执行。部分操作类型有审批有效期（外发类 2 小时，其余 24 小时），过期未处理的卡片会明确提示「已过期」，需要让 Agent 重新发起，不会静默执行。

## 待回邮件：按线程收拢

同一条线程只占一行，默认折叠，标出最久一封的等待时长。用不着回的，标一句「无需回复」——可以整条线程标，也可以只标其中一封，标错了随时撤销。已经标过「无需回复」的线程，之后如果又来了新邮件，照常会重新出现在待回列表里，不会被永远压住。邮件重新同步后，这个标记也不会丢。

## 刷新时机

今日页不需要手动刷新。以下几个时机会自动重新拉取：日期跨过午夜、窗口重新可见、窗口重新获得焦点；前台停留时每 90 秒还会兜底刷新一次。读取失败时会明确提示「加载失败」，不会悄悄显示成一个空列表让你误以为真的没事。

:::note[今日 ≠ 通知中心]
两者不是一回事：今日汇总的是「现在还等着你处理的状态」，条目会随着你处理完而消失；通知中心记录的是「发生过的事件」，处理完之后仍留在历史里可查。同一件事——比如一次待批的审批——可能两边都看得到：今日告诉你「现在还等着」，通知中心告诉你「刚才发生过一次暂停」。详见[通知中心](/101/notifications/)。
:::

## 常见问题

- **智能体产出里的报告点进去是什么？** 直接跳到对应的报告详情页，能看到完整内容而不只是摘要。
- **审批卡上的操作不想马上决定？** 可以先不处理，它会一直留在「等你拍板」里，直到你处理或它过期。
- **待回邮件一直不消失？** 检查它是不是还没被标为已读或已处理，或者用「无需回复」把它移出这个列表。
