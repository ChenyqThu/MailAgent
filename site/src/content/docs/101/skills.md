MailAgent 里，AI 的每一类能力都打包成一个「技能」（Skill）——工具本身，加上怎么用这些工具的说明。技能决定 AI 知道什么、能碰什么；管理入口在 设置 → AI →「技能」。

## 技能列表看什么

列表按来源分三类：内置（产品自带，可信）、用户创建（你在对话里让助手整理出来的）、第三方（你自己安装的技能包）。每一项显示是否已启用、对外 API 工具数、权限范围；点进详情能看到当前包哈希、读写范围与网络模式。

关闭一个技能，它带来的工具与提示词指引不会注入下一次对话——这一步只影响这一整包能力在不在，具体每个工具的执行审批档位另外设置。

:::note[技能开关不等于工具审批档]
「技能」这里管的是一整包能力在不在。Skill 供应链、Custom Agent 配置这类由技能驱动的对话内工具，实际的先确认 / 直接执行设置在「权限与审批」页，不在这张开关卡片上，见[权限与审批](/101/approvals/)。
:::

## 安装第三方技能包

在对话里让助手安装一个外部技能包，下载、解包、校验的每一步都会先让你确认——这属于「Skill 供应链」这组恒需确认的操作，完整流程见[权限与审批](/101/approvals/)。安装完成后，技能出现在列表里，来源标为「第三方」。

## 在对话中把工作方法整理成技能

不必自己写代码。跟助手描述一套你常用的工作方法，它会：

1. **起草**——生成一份技能草稿，写入草稿区（设置 → AI 里可见），并跑一遍静态校验；
2. **确认**——弹出发布确认卡，展示这份草稿包含哪些文件、校验结果是什么；
3. **发布**——你确认后才真正安装，是否同时启用由确认卡上的选项决定。

草稿区里的脚本在任何情况下都不会被执行，哪怕还没到发布这一步——这是产品的硬性保证，不受任何设置影响。

## 信任特定版本

安装好的第三方或自建技能，可以在技能列表里把当前版本标记为「信任」，此后自定义 Agent 执行这个版本的脚本不用逐次确认。技能文件只要发生任何变化，这份信任就会自动失效、显示为「已过期」，需要你重新确认。

## 导入导出

技能可以导出成压缩包，两种格式二选一——技能格式，或者更通用的 Agent Plugin 格式。也可以反过来，导入外部的 Agent Plugin 压缩包或目录。导入进来的组件会先落进草稿区，仍然要走完发布与信任的完整流程；包里如果声明了 MCP 服务器，只作展示，不会自动连接或授权。

## 对外交付

如果你想把某个技能作为标准接口开放给别的 agent 或脚本调用，这属于开发者向的能力，见 [Skill 交付 API](/agent/skill-delivery/)。

## 常见问题

- **技能列表里显示「0 个工具」是不是坏了？** 不一定。列表统计的是对外 API 工具数；有些技能（比如驱动 Skill 供应链、Custom Agent 管理的那两个）靠的是对话内工具，其审批档位在「权限与审批」页，不计入这个数字。
- **发布技能会立刻生效吗？** 会，发布即安装。
- **信任过期了要怎么办？** 回到技能列表，重新点一次「信任此版本」，前提是你已确认过文件的这次变化没问题。
