MailAgent 在后台做的事很多：同步邮件、跑 AI 分类、执行自定义 Agent、生成报告。这些事完成、失败或需要你处理时，都会落到标题栏的铃铛里——通知中心是它们唯一的落脚点。

## 和「今日」的区别

两者不是一回事。**今日**是一份「现在还等着你处理」的清单，条目随你处理完而消失；**通知中心**是一份事件记录，处理完之后仍留在「已处理」里可以回看。同一件事——比如一次暂停待批的 Agent 运行——可能两边都看得到：今日告诉你「现在还等着」，通知中心告诉你「刚才发生过一次暂停」。详见[今日](/101/today/)。

## 铃铛上看到什么

点标题栏的铃铛图标打开面板。未读数以数字角标显示（超过 99 记「99+」）；如果未读里有严重告警，铃铛会显示红点而不是普通计数。

面板顶部是「全部标为已读」，下面是五个分类：

| 分类 | 收的是什么 |
|---|---|
| 全部 | 不筛选，按时间倒序 |
| 待办 | 需要你处理的——比如一次暂停等待审批的 Agent 运行 |
| 审阅 | 需要你看一眼再决定的——比如跟进 Agent 提出的事项更新提案、通讯录的治理建议 |
| 结果 | Agent 运行、后台维护任务、报告生成的终态 |
| 系统 | 系统告警——同步不健康、飞书连接断开、DavMail 需要重新认证 |

通知按「今天 / 昨天 / 更早」分组；同一件事重复发生会在同一条上计次（比如某个告警连续触发三次，显示「×3」），不会刷屏成三条。

## 信源覆盖

会推送到通知中心的事件包括：Agent 运行完成或失败、Agent 运行暂停等待审批、跟进 Agent 提出的事项更新提案与需要留意的信号、事项跟进硬失败、报告生成完成、通讯录待审建议、后台维护任务（如重新同步、批量补抓）终态、系统告警（同步服务不健康、死信积压、DavMail 需要重新认证或被限流、飞书对话连接断开、Redis 事件消费断连、后台 worker 崩溃或崩溃循环）、资料库的无人值守写入、应用更新已下载就绪、后台运行完的 AI 对话。

## 对一条通知能做什么

鼠标悬停在一条通知上，右侧会出现「更多操作」菜单：

- **稍后提醒**：1 小时后、明天早上，或 3 天后再提醒你。
- **标记为已处理**：从当前列表移出，进入「已处理」历史，不会再打扰你。

点通知本身会先标记已读，再跳转到对应的位置——邮件、事项、会话、报告或设置页，取决于这条通知的来源。

系统告警会自愈：触发它的问题恢复后（比如 worker 重新变得健康），对应的告警条目会自动标记恢复，不需要你手动清理；DavMail 授权在临近过期前也会分级预警，给你留出重新认证的时间。

## macOS 原生通知

严重告警和「待办」类通知，除了落进通知中心，还会额外弹一条 macOS 系统通知，点击直接聚焦到 MailAgent 窗口并跳到对应位置。其余类别只在铃铛上体现，不弹系统通知，避免打扰。

## 常见问题

- **通知中心和灵动岛通知是一回事吗？** 不是。[灵动岛](/101/ping-island/)是一个可选的独立增强，展示重要邮件的即时提醒；通知中心是应用内置、始终可用的持久化通知面，覆盖的信源也更广。两者可以同时开着。
- **标记已处理的通知还能找回来吗？** 面板的「已处理」历史里能看到，不会被删除。
- **为什么有些通知没有恢复提示？** 少数信源（比如外部服务的授权失败）目前只在出问题时发一条，没有对应的「已恢复」信号；读到之后铃铛角标会清掉，条目本身需要在面板里手动标记已处理。
