报告 Agent 把这段时间收了哪些邮件、哪些已经处理、哪些还要你亲自看、事项进展到哪了这件事，浓缩成一份可以直接读完的内容。日、周、月三种周期自动生成，不用自己翻收件箱回顾。

## 内容包含什么

一份内容通常按四块组织：

1. **总览**——一段话概括这段时间的整体情况；
2. **统计卡**——总数、未读、紧急、AI 已处理、待处理这些数字；
3. **分组明细**——「需要你关注」（还得你亲自处理的）、「AI 已处理」（已经分类或起草过的）、「FYI / 一般」（知道一下即可）；
4. **事项汇总**——这段时间里，你关注的事项有了哪些进展。

每一封邮件都是一行可点击的条目，点开直接打开这封邮件；如果启用了 Notion 镜像，也能跳到对应的 Notion 页面。

:::tip[数字不是模型编的]
里面的统计数字、链接、邮件归属，全部由代码按真实数据算出来再填进内容里；AI 只负责写总览、点评这些文字部分。模型自己给出的编号会被校验，编造的会被丢弃，不会出现在最终内容里。
:::

## 日 / 周 / 月的区别

| 周期 | 覆盖窗口 | 侧重 |
|---|---|---|
| **日** | 过去 24 小时 | 逐封策展明细（关注 / 已处理 / FYI） |
| **周** | 过去 7 天 | 趋势 + 跨项目进展 |
| **月** | 过去 30 天 | 高层回顾 + 趋势图 |

## 在哪看

这是一个独立的一级域：左侧二级栏是内容列表，选中一份直接看正文。

每一份都对应团队页里的一次 Agent 执行——在团队页找到对应的成员（比如「日报」），它的记录时间线上会有这次执行；执行详情本身就是一份完整的对话记录，触发、思考、调用工具、产出结果按时间展开。产出了内容的执行，可以在记录详情里直接展开正文，默认折叠，展开时才加载。

## 排程

排程用点选完成，不用记 cron 表达式：每天几点、每周哪天几点，选好就成，界面会用一句话告诉你选的是什么（比如「每 2 周 周二、周四 9:00 AM」），并列出接下来 5 次的真实运行时间。当天错过的排程时段，应用重新开机后会补上一次。

## 怎么启用

这个 Agent 默认关闭，分两层：

1. **总开关**（`.env` 里的 `MAILAGENT_REPORT_AGENT_ENABLED`，改完需要重启后端）；
2. **具体某个 agent**（日 / 周 / 月）需要在团队页里单独打开。

两层都要打开才会真正生成。想立刻验证，不用等到下一个排程时间点，在团队页对应 agent 的配置面板点「立即运行」即可。

## 和知识大脑的关系

如果开启了知识大脑（KOS），生成时可以按需检索知识库，给跨项目进展、某个发件人或公司的背景补充上下文。这是可选增强，关着也能正常生成。

## 常见问题

- **开了开关，第二天没看到？** 确认总开关和团队页里对应 agent 都已启用；想立刻验证就用「立即运行」。
- **某天没什么重要邮件？** 内容会是空态（比如「这段时间无需特别关注的邮件」），这是正常情况。
- **措辞想改？** 在团队页对应 agent 的配置面板里改提示词，下次生成即生效。
