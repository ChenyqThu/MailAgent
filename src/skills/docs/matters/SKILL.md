# Skill: matters

Follow up a Matter — a tracked piece of work that owns a status, action items, stakeholders, linked
evidence (emails, documents, calendar events), and a timeline. This skill is the working method. It
adds no tools of its own: the Matter tools live in the desktop AI gateway, are available whenever the
Matters feature is on, and keep their own approval cards.

## When this applies

- The user names a Matter (for example MAT-0042), or asks about "this项目 / this thread / where does
  X stand".
- The user asks to create a Matter from an email, a document, or a conversation.
- A follow-up run asks what changed and what should happen next.

## Workflow

1. **Find before you create.** Search with the user's own wording. Report which existing Matters you
   checked. Join or update the matching one; create a new Matter only when nothing matches.
2. **Read the evidence before judging progress.** Fetch the Matter with a bounded include set (open
   items, stakeholders, pinned resources, recent timeline) rather than inferring from the title.
3. **Separate evidence from inference.** State what the linked material actually shows, then what you
   infer. When the evidence does not reach far enough, name the gap instead of filling it.
4. **Write the smallest thing that records the change.** Add a note, close one item, or add a
   stakeholder. Rewrite the current summary only when the evidence supports a new state.
5. **Draft, do not send.** A follow-up email is prepared for the owner to review. Sending is the
   owner's action.
6. **Report only confirmed results.** Every write returns a receipt with an undo descriptor and goes
   through an approval card. A rejected, failed, or missing result is not a change.

## Scope discipline

A Matter conversation can search the whole mailbox or only this Matter's own evidence. Respect the
scope the owner selected; when a question genuinely needs material outside the Matter, ask for the
wider scope instead of quietly reaching for it.

## What does not belong in a Matter

Conversation history is not Matter knowledge. Only tool writes, accepted updates, and deterministic
events become part of the record — so if something should survive this conversation, write it.
