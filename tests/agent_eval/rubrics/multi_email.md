# Rubric — multi_email（跨多邮件/线程聚合）

软评分锚点（LLM judge manual lane）。每维 0 / 0.5 / 1。权重见各 task.rubric。
**硬闸是 R4（每个 expected_evidence 必须出现）+ R8（evidence 必须有据）。**

## answer_correctness
- 1：把多封邮件的关键事实正确聚合成一个连贯答案（如两条线程合并出统一结论/金额/时间线）。
- 0.5：聚合方向对但漏掉一条来源的关键信息。
- 0：只看了一封就下结论，或把不同邮件的事实张冠李戴。

## evidence_grounding
- 1：答案显式列出**所有**关键来源的 `internal_id`，每个 id 都确为对应事实出处。
- 0.5：只给了部分来源 id，或给了 id 但有一个对不上。
- 0：无 id，或 id 与结论无关。

## uncertainty_honesty
- 1：来源间有冲突时点明冲突并说明如何取舍；信息不全时说清缺口。
- 0.5：略过冲突但未误导。
- 0：把不一致的来源强行拼成确定结论。

## tool_efficiency
- 1：按需检索 + 精读各线程一次到位，无重复拉同一封。
- 0.5：有 1-2 次冗余检索/重复精读。
- 0：反复检索仍漏读关键邮件，或空转到 max_iter。

## ux_clarity
- 1：答案结构清晰（如按线程/主题分点 + 每点带 id），用户一眼看懂各结论来自哪封。
- 0.5：结构平铺但可读。
- 0：把多封内容糊成一团，无法溯源。
