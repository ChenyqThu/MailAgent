## 3. 远程 + 本地 e2e runbook（A 块 —— 最重，ground truth + 坑）

### 3.1 关键前提：必须 build feature 分支 .app + 部署 feature serve-api
现有装机 `.app` = **v0.3.0（main，无 3c chat cutover）** —— 3c-3 实测它 serve-api smoke `/api/chat/config` 返 **404**（旧版无 3c-1 端点）。所以 3c-5 e2e 必须：
1. **build feature 分支 `.app`**（含 3c-1~3c-4 全部 renderer cutover + 3b/3c-1 serve-api 端点）。
2. **部署 feature serve-api**（本地 serve-api + cloudflared，或远程；serve-api 读 app 库 `~/Library/Application Support/mailagent-frontend/data/sync_store.db` + `DATA_ROOT/frontend/ai_chat.db`）。

### 3.2 build .app 四坑（CLAUDE.md「打包/发布」+ memory，逐个踩过）
1. 🔴 **venv 重 provision**：3c-4 改了 `src/electron/main/notion_agent/config.ts`（前端 TS，不影响）；但若本轮 lint/orphan 动了 Python（不该有），或换机/新 clone → 必 `bash frontend/scripts/build-python-venv.sh`（venv 非 editable，旧 provision = 旧后端）。本轮纯前端则可跳过 Python 重 provision，但 `resources/python` 必须在（缺失 → afterPack 跳过签名 → codesign FAIL）。
2. 🔴 **ABI 切回 Electron**：本 session 跑过 vitest（better-sqlite3 = Node ABI）→ **build 前必 `pnpm rebuild:electron`**（否则装进 app 的 `better_sqlite3.node` ABI 不匹配 → 所有 SQLite IPC 崩 + 启动卡 120s）。验证：`ELECTRON_RUN_AS_NODE=1 ./node_modules/.bin/electron -e "require('better-sqlite3')"` 不报错。
3. 🔴 **含远程 web 必 `pnpm build:web`**：装机用 `pnpm run build && npx electron-builder --dir --arm64` **不含** web SPA → 远程根 `/` 返 `{"detail":"Not Found"}`。要远程必 `pnpm build:web && ...`（`build:mac` 已含）。
4. afterPack codesign EAGAIN（完整 build 首跑必撞）已加 retry 根治（`afterPack.cjs codesignWithRetry`）。
- 验证：`codesign --verify --deep --strict <app>` OK + `Resources/python/bin/python3.11` 在 + `Info.plist` 版本号对。
- 装机：退出旧 app + 停 pm2 `mail-sync`（防双写）→ `ditto dist/mac-arm64/MailAgent.app /Applications/` → open。

### 3.3 部署模型（V2 remote，已 ship v0.3.0 验证过基础设施）
- serve-api FastAPI **8200**（`MAILAGENT_REMOTE_ACCESS_ENABLED` 默认起，纳入 BackendLifecycleManager 自启）→ cloudflared → CF Access（team **`tplinkomada`**，是个人账号别误判公司）。
- 本地腿：`chat_local_bridge` webRequest 给 loopback 8200 注本地 token（renderer 不持 token）；远程腿：CF cookie + 白名单 origin（`ALLOWED_ORIGINS=["https://mail.chenge.ink"]`）。
- ⚠️ serve-api CLI **不 auto-load .env**（`mailagent serve-api` 直跑需完整 `.env`，config.py 必填 5 项否则 crash）；打包态由 BackendLifecycle 注入 env。

### 3.4 e2e 测什么（本地 electron renderer + 远程 mail.chenge.ink/app 对照 parity）
- **custom-api**：单轮 + 多轮 + 读工具（email_list/get/search…）+ **写工具确认弹窗**（flag/archive → ConfirmToolDialog → confirmTool → 同进程 resolveConfirmation）。
- **notion-agent**：多轮 + thread 续接（验 D4 的 metadata thread_id 持久化）+ 工具展示行（验 D4 tool_call → role=tool）+ **回复无多余尾换行**（验 codex MEDIUM 修的 finalContent parity）。
- **KOS 保存**（✨ 保存到 KOS）+ 行内编辑重跑 + abort + 新建会话 + 会话历史跨邮件。
- **打包态 file:// CORS 腿**（renderer Origin `null` → webRequest 注 CORS）—— 3c-1 加的，真机首次验证。
- 远程「AI 未配置」边界：远程能否配 LLM key / 跑 chat（serve-api 读 `config.llm_api_key` 仅 env）。

### 3.5 e2e 工具
- 本地 electron renderer：`pnpm dev` 或装机 `.app`，开邮件详情 → AI chat 面板跑上述。
- 远程：浏览器开 `mail.chenge.ink/app`（CF Access 登录）→ 同样跑。
- 可用 playwright MCP / chrome MCP 驱动远程 web（dom-aware）；本地 electron renderer 真 e2e 靠手动 + 截图（或 spectron/playwright-electron 若已配）。
