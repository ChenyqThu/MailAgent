# V2.1 远程 chat + report/agent 端点补全 — Handoff

> **起因**：v0.3.0 真机验收时发现，远程 `mail.chenge.ink/app` **看不到 AI 对话记录 / Agent 列表 / Agent 报告**。
> **定性**：不是 bug，是 V2 remote（Sprint 3/4）**有意的减法上线** —— HttpApi 注释明写「chat.* stay as notImplemented / SSE deferred to V2.1」。本文件是 V2.1 的补全清单。

## 根因（已诊断）

| 功能 | 数据在哪 | serve-api 端点 | 远程客户端 | 为什么远程空 |
|---|---|---|---|---|
| AI 对话记录 | **单独库 `ai_chat.db`**（非 sync_store.db）| ❌ 无 chat router | `chat.*` 全 `notImplemented` | serve-api 没读这个库 + 无端点 + 客户端 stub |
| Agent 列表 + 报告 | **`sync_store.db`**（serve-api 已连，有数据）| ❌ 无 reports router | `ReportApi` 类型已 import 但未接 | **数据在库里，只缺端点** |

本地 Electron 走 IPC 直读库（能看到）；远程 web 走 HttpApi → serve-api → 缺端点 → 空。

## 目标验收

远程 `mail.chenge.ink/app` 能：① **查看** Agent 列表 + Agent 报告 ② **运行 + 与 LLM 多轮对话**（chat agent）。

---

## Part A — report/agent 远程（中等；数据已在 serve-api 读的库，纯读为主）

新增 `src/api/routers/reports.py`，镜像 `frontend/src/electron/main/handlers/report.ts` 的 IPC：

| 端点 | 镜像 IPC | 实现要点 |
|---|---|---|
| `GET /api/reports` | `report:list` | 直读 `sync_store.db` `report` 表（serve-api 已连此库；不含 blocks_json）|
| `GET /api/reports/{id}` | `report:get` | 读 `report.blocks_json` → ReportDoc |
| `GET /api/report-agents` | `report:getConfig` | 读 `report_agent` 表 |
| `PUT /api/report-agents/{id}` | `report:setConfig` | 写 —— in-process 复用 `src/reports/store.py::ReportStore`（**比 report.ts 的 CLI fork 更优**，沿用服务化重构 in-process 范式）|
| `POST /api/report-agents/{id}/run` | `report:runNow` | 触发生成 —— 走 **async_jobs（C1 子系统）** 或直调 `src/reports/worker`；长任务进度复用 `job.*` SSE |
| `DELETE /api/report-agents/{id}` | `report:delete` | `ReportStore` 删 |

**HttpApi**：`ReportApi` 去 stub，接上述端点（`ReportListItem`/`ReportDetail`/`ReportAgentConfig` 类型已 import，前端 report UI 已备）。

## Part B — chat 远程（大；单独库 ai_chat.db + SSE 流式 agent）

新增 `src/api/routers/chat.py`，镜像 `frontend/src/electron/main/handlers/chat.ts`：

| 端点 | 镜像 IPC | 实现要点 |
|---|---|---|
| `GET /api/chat/sessions?emailId=` | `chat:listSessions` | **读单独库 `ai_chat.db`**（serve-api 需配 `AI_CHAT_DB_PATH` 或新连接，路径 `<DATA_ROOT>/frontend/ai_chat.db`，见 `chat_db.ts`）|
| `GET /api/chat/sessions/all` | `chat:listAllSessions` | |
| `GET /api/chat/sessions/{id}/messages` | `chat:listMessages` | |
| `GET /api/chat/sessions/{id}/tool-calls` | `chat:listToolCalls` | |
| `GET /api/chat/kos-available` | `chat:kosAvailable` | KOS 集成探测 |
| `POST /api/chat/start` | `chat:start` | 起 session + agent harness |
| `POST /api/chat/send` | `chat:send`（多行 handler）| 发消息 → agent dispatcher（多轮）|
| `POST /api/chat/abort` | `chat:abort` | 中止 in-flight stream |
| **`GET /api/chat/stream` (SSE)** | `chat:stream`（本地 `webContents.send` server-push）| **🔴 流式 token 改 SSE 推** —— 远程无 webContents；复用 `events_bridge` / `sse_server.py` SSE 范式 |

**HttpApi**：`chat.*` 去 `notImplemented`，SSE 接 `/api/chat/stream`。

### Part B 的硬骨头
- **流式**：本地 `chat:stream` 是 Electron 专属 `webContents.send`；远程必须改 SSE（serve-api push token）。这是 Part B 工作量大头。
- **agent dispatcher 在 serve-api 进程跑**（不是 Electron main）—— 确认 `MAILAGENT_AGENT_HARNESS` + KOS 工具桥的依赖在 `mailagent serve-api` 进程可用。
- **ai_chat.db 连接**：serve-api 当前只连 `sync_store.db`（app 库），要新增 ai_chat.db 连接。

## 鉴权

chat/reports router 同样 `Depends(verify_cf_access)` —— 复用 C2 双层鉴权（本地 token + CF Access），零额外工作。

- V2 remote 既有：memory `project_v2_remote_web_access`（serve-api 读 app 库 / cloudflared / CF Access）

## 建议拆分

Part A（report/agent）先做 —— 数据已在库、纯读为主、写端点 in-process 复用 ReportStore，可较快出远程「能查看 Agent 列表/报告」。Part B（chat SSE 流式）单独一段 —— 流式 + agent dispatcher 跨进程是硬骨头。
