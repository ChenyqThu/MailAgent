# 多文件夹同步 PRD（Multi-Folder Sync）

> 让用户自主勾选并同步 Exchange 邮箱里的多个自定义文件夹，使这些文件夹的邮件享受与收件箱完全一致的能力（AI 分类 / Notion 同步 / 通知 / 线程 / 搜索 / 全套读写）。
>
> **状态**：需求定稿，待设计稿 + 技术设计评审
> **关联技术设计**：[`docs/multi-folder-sync-design.md`](./multi-folder-sync-design.md)
> **决策基线**：完整 pipeline · 完整写操作 · 白名单手动勾选 · davmail-only（见 §7 决策记录）
> **最后更新**：2026-06-08

---

## 1. 需求背景

### 1.1 现状

MailAgent 当前只同步两个**写死**的文件夹：

- **收件箱**（IMAP `INBOX`）—— 主路径
- **发件箱**（IMAP `Sent Items`）—— 仅当 `SYNC_MAILBOXES` 含「发件箱」

davmail 取数主循环 `get_new_emails()` 把同步目标硬编码成这两个，`SYNC_MAILBOXES` 配置虽然形式上是逗号分隔列表，但实际只被用来判断「要不要同步发件箱」，其它文件夹名被静默忽略。

### 1.2 痛点

公司 Exchange 邮箱用户普遍用 **Outlook 规则**把邮件自动分流到自定义文件夹。**实测该用户邮箱有 18 个文件夹**，大量有价值的邮件落在自定义文件夹里：

| 文件夹 | 邮件量（实测） | 性质 |
|---|---|---|
| Jira | 3458 | 项目协作通知 |
| DMS固件发布 | 728 | 研发发布通知 |
| Notion | 381 | 协作平台通知 |
| Bugzilla / Confluence / Figma | — | 工具链通知 |
| 待办 / 必要文档路径 / 对话历史记录 | 0~少量 | 个人归类 |

这些文件夹的邮件目前**完全在 MailAgent 视野之外**：看不到、不分类、不进 Notion、不通知。用户仍需切回 Outlook 才能查看——违背了 MailAgent「统一邮件中枢」的产品定位。

**更隐蔽的副作用 —— 收件箱状态漂移**：Outlook 规则通常「邮件先投递到收件箱(INBOX)，规则再移走到文件夹」。MailAgent 秒级轮询 INBOX，于是常**抢在规则移走前抓到**邮件、以 `mailbox=收件箱` 同步入库；之后 Outlook 把它移到目标文件夹，但 MailAgent 不跟踪移动，记录**定格在抓取那一刻**。后果：① MailAgent 收件箱里看到的部分「类通知」邮件，在真实 Outlook 里其实早被移到文件夹（**收件箱被污染**）；② 只有靠 INBOX 窗口期「漏网」的才进来，服务器端规则直投 / 错过窗口的完全缺失。本功能落地后，这些邮件**按真实所属文件夹正确归类**，同时消除收件箱漂移。

### 1.3 可行性（已实测验证）

davmail（EWS↔IMAP 桥）已被实测证明完全具备能力：

- **列得出**：一条 IMAP `LIST "" "*"` 返回全部 18 个文件夹，含所有自定义文件夹，中文名经 modified-UTF7 解码后可读。
- **进得去、取得到**：对自定义文件夹 `SELECT` + `UID SEARCH` 成功取到邮件（Jira 3458 封、Notion 381 封、DMS固件发布 728 封均验证）。
- **有增量游标**：每个文件夹都有独立的 `UIDVALIDITY` / `UIDNEXT`，per-folder 增量同步可行。

> 详见技术设计文档 §2 现状与实测结论。

## 2. 目标与非目标

### 2.1 目标

1. **文件夹发现**：用户能看到自己 Exchange 邮箱里的所有（可同步的）文件夹列表。
2. **白名单勾选**：用户自主勾选要同步哪些文件夹（默认一个不选，避免大文件夹无脑全量灌入）。
3. **完整能力对齐**：勾选的文件夹，其邮件享受与收件箱**完全一致**的全套能力——AI 分类、Notion 同步、飞书通知、线程关系、全文搜索、附件处理，以及标旗/已读/归档/移动/回复/转发等全套读写操作。
4. **主菜单栏呈现**：在左侧 Sidebar 动态呈现已勾选的文件夹，点击即可查看该文件夹的邮件列表。
5. **Onboarding 集成**：新用户 onboarding 流程加入「勾选要同步的文件夹」环节，开箱即配。

### 2.2 非目标（首期不做）

| 不做 | 原因 |
|---|---|
| AppleScript 后端支持 | davmail-only（决策）；AppleScript 对中文文件夹名有匹配坑，作未来扩展 |
| 文件夹的创建/删除/重命名/管理 | 只读文件夹**结构**，不做文件夹管理；用户在 Outlook 侧管理 |
| 嵌套子文件夹层级树 | 首期平铺呈现（实测当前文件夹都是顶层）；层级树作未来扩展 |
| 共享邮箱 / 委托邮箱 / 在线存档（In-place Archive）的文件夹 | davmail 普通 IMAP 不暴露这些；超出范围 |
| 文件夹同步深度的逐个差异化配置 | 决策为统一「完整 pipeline」；不做 per-folder 深度可配 |

## 3. 用户故事

- **US-1**：作为研发，我希望 Jira / DMS固件发布 文件夹的邮件也能被 AI 分类、推送重要通知，这样我不会漏掉项目里的关键变更。
- **US-2**：作为新用户，我希望在 onboarding 时就能看到自己邮箱有哪些文件夹并勾选要同步的，而不是装完才发现只同步了收件箱。
- **US-3**：作为日常使用者，我希望在左侧菜单栏直接点开「Notion」文件夹看里面的邮件，而不用切回 Outlook。
- **US-4**：作为重度用户，我希望在自定义文件夹里也能直接回复/转发/归档邮件，操作体验和收件箱一致。
- **US-5**：作为谨慎的用户，我希望默认不要把 3458 封的 Jira 文件夹一股脑同步进来，让我自己决定同步哪些、什么时间窗口。

## 4. 功能需求

### 4.1 文件夹发现（Folder Discovery）

- 系统能调用后端拉取当前账户**可同步的文件夹列表**（经 davmail IMAP LIST）。
- 列表项至少包含：**显示名**（中文/英文，已解码）、**邮件总数**、**是否已勾选同步**、**是否系统文件夹**（INBOX/Sent/Drafts/Junk/Trash 等标记区分）。
- 系统文件夹（收件箱/发件箱）默认已同步且不可取消（保持现有行为）。
- 发现结果可刷新（用户在 Outlook 新建文件夹后，能重新拉取看到新文件夹）。

**验收**：在配置页点击「刷新文件夹列表」，能看到实测的 18 个文件夹，中文名正确显示，每个带邮件数。

### 4.2 配置页（Settings → 同步 Tab）

在现有 **Settings「同步」Tab** 的「文件夹同步」区（当前是存档/草稿箱开关）扩展/重构出一个 **文件夹选择器**：

- **文件夹列表**：以可勾选列表（checkbox list）呈现 §4.1 的发现结果。每行：勾选框 + 文件夹显示名 + 邮件数徽标 +（可选）同步状态/最近同步时间。
- **勾选交互**：勾选 = 加入白名单；取消 = 移出白名单（移出时提示「已同步的本地邮件会保留/清理」——见 §6.3 边界）。
- **同步窗口控制**（沿用现有存档同步的范式）：
  - 首次同步窗口（最近 N 天）—— 防止大文件夹全量灌入
  - 单文件夹同步上限（最多 N 封）—— 防极端大文件夹
- **保存即生效**：保存后写入配置，后端 worker 据此增量同步（配置变更需后端重启或热加载，沿用现有 `.env` restart=yes 范式）。
- **空态**：未发现任何自定义文件夹时，显示引导文案（「未检测到自定义文件夹，请确认使用 davmail 后端」）。
- **后端门控**：仅 davmail 后端可用；AppleScript 模式下该区禁用并提示。

> 设计稿重点：把「发现 → 勾选 → 窗口设置 → 保存」做成一个清晰的配置流，参考现有 `EnvField` + `Section` 的声明式风格，但文件夹列表是**动态从后端拉取**的（非纯 .env 文本），需要新的列表控件。

### 4.3 Onboarding 流程优化

在现有 onboarding 流程（约 7 步，含账户配置/邮箱多选/权限/完成）中，**在邮箱配置之后、完成之前**插入一个 **「选择要同步的文件夹」步骤**：

- **触发条件**：仅 davmail 后端用户显示此步（AppleScript 用户跳过）。
- **步骤内容**：拉取文件夹列表 → 多选勾选 → 说明「可稍后在设置里修改」。
- **默认态**：收件箱/发件箱默认勾选且锁定；自定义文件夹默认全不选（白名单），用户按需勾。
- **大文件夹提示**：对邮件数很大的文件夹（如 >1000 封）给出轻量提示「该文件夹较大，首次同步可能较慢」。
- **可跳过**：用户可不勾任何自定义文件夹直接完成（= 当前行为，只同步收件箱/发件箱）。
- **落盘**：勾选结果与其它 onboarding 配置一起落盘（同现有配置写入路径）。

**验收**：新用户 onboarding 能看到文件夹选择步骤，勾选后完成，启动后这些文件夹开始同步并出现在 Sidebar。

### 4.4 主菜单栏（Sidebar）文件夹呈现

在左侧 Sidebar 的 **MAILBOXES 段**（现有：收件箱/发件箱/标旗/全部 + 存档/草稿箱），**动态追加已勾选的自定义文件夹**：

- **呈现**：每个已同步的自定义文件夹一行（图标 + 文件夹名 + 未读/总数徽标），复用现有 `NavRow` 行样式与计数徽标（`CountRight`）。
- **约束**：受 Sidebar §2.11「只能三个 section header（MAILBOXES/AI AGENTS/VIEW）」的 lint 约束——自定义文件夹**必须挂在 MAILBOXES 段内**，不得新增 section header。
- **折叠**：自定义文件夹较多时，考虑「展开/收起更多文件夹」的折叠控件（避免 Sidebar 过长）。
- **点击行为**：点击某文件夹 → 邮件列表按该 folder 过滤呈现（同收件箱列表的交互/性能，复用现有列表虚拟化与查询缓存）。
- **计数刷新**：folder 计数走现有 SSE（`folder.synced` 事件 invalidate）+ 轮询兜底。
- **图标**：自定义文件夹用统一的「文件夹」图标（区别于收件箱/发件箱的语义图标）。

**验收**：勾选了 Notion 文件夹后，Sidebar 的 MAILBOXES 段出现「Notion」行带邮件数，点击后右侧列表只显示 Notion 文件夹的邮件。

### 4.5 邮件能力（完整 pipeline 对齐）

自定义文件夹的邮件在「功能表现」上与收件箱**完全一致**：

| 能力 | 表现 |
|---|---|
| **列表/详情** | 与收件箱一致的列表（虚拟化、线程折叠、snippet）+ 详情正文（iframe）+ 附件 |
| **AI 分类** | 走 LLM Agent（优先级/动作/审阅状态），与收件箱同一套 |
| **Notion 同步** | 同步为 Notion 页面，`Mailbox` 字段写文件夹名（Select 自动建 option） |
| **通知** | 重要邮件走飞书通知（与收件箱同策略；大通知文件夹可能需降噪——见 §6.4） |
| **线程** | 线程关系（Parent Item）正常关联 |
| **搜索** | 进入 FTS5 全文搜索，跨文件夹可搜 |
| **读操作** | 标已读/未读 |
| **写操作** | 标旗、归档、**移动到其它文件夹**、回复、回复所有、转发（SMTP 真实发送） |

**关键**：写操作（标旗/已读/归档/移动）统一走现有 outbox SSoT + FanoutWorker 异步派发；归档/移动需从「写死 INBOX→Archive」泛化为「任意源文件夹 → 任意目标文件夹」。

## 5. 交互流程

### 5.1 首次配置（Onboarding）
```
账户配置 → 邮箱多选 → 【新】拉取文件夹列表 → 勾选要同步的文件夹 → 权限/完成
                                  ↓
                        落盘白名单 → 启动后端 worker
```

### 5.2 后期管理（Settings）
```
Settings → 同步 Tab → 文件夹同步区 → 刷新文件夹列表
   → 勾选/取消 + 调整同步窗口 → 保存 → 后端按新白名单增量同步
```

### 5.3 日常使用
```
Sidebar MAILBOXES 段 → 点击「Jira」文件夹 → 右侧列表按 folder 过滤
   → 打开邮件 → 查看/AI 优先级/回复/归档/移动（与收件箱一致）
```

## 6. 边界与降级

### 6.1 大文件夹
Jira 实测 3458 封。首次同步必须受**窗口（最近 N 天）+ 上限（最多 N 封）**双重约束，分批拉取，避免阻塞主同步与撑爆 Notion/LLM。默认窗口建议保守（如最近 90 天 / 上限 2000 封），用户可调。

### 6.2 davmail-only
AppleScript 后端下，文件夹发现/选择/同步整体禁用，UI 明确提示。

### 6.3 取消勾选某文件夹
取消同步后，该文件夹**已同步的本地邮件与 Notion 页面**如何处理需明确（建议：默认保留，提供「同时清理本地数据」选项）。详见技术设计 §写操作与一致性。

### 6.4 通知降噪
自动化通知文件夹（Jira/Bugzilla）若全部走飞书通知会造成骚扰。需要 per-folder 通知开关或默认对自定义文件夹关闭通知（产品待定，建议默认**不通知**，仅 AI 分类 + Notion 归档；通知作为 per-folder 可选）。

> ⚠️ 此项与决策「完整 pipeline」有张力——「完整」指能力齐备，但通知是否默认开启需产品定调。**建议**：自定义文件夹默认 AI 分类 + Notion 同步 + 入列表/搜索，但**通知默认关**，可在配置里逐文件夹打开。

### 6.5 合规约束（继承项目死硬约束）
- davmail 当前是 PoC（well-known client_id 伪装），**不可上生产**；本功能在 PoC 阶段 dogfood，正式落地需走公司 IT 审批 / Graph API。
- EWS 2026-10-01 退役，davmail 走 EWS，长期需迁移 Graph。

## 8. 验收标准（产品侧）

1. **发现**：davmail 用户在设置页能拉取并看到全部自定义文件夹（含中文名 + 邮件数）。
2. **勾选**：勾选 N 个文件夹保存后，后端开始同步这些文件夹；取消勾选后停止同步新邮件。
3. **完整能力**：自定义文件夹的新邮件能被 AI 分类、同步到 Notion（Mailbox 字段正确）、进入全文搜索、正确归入线程。
4. **Sidebar**：已同步文件夹在 MAILBOXES 段呈现，计数正确，点击过滤正确。
5. **写操作**：在自定义文件夹内能标旗/标已读/归档/移动/回复/转发，且变更正确双向同步。
6. **Onboarding**：新用户能在 onboarding 勾选文件夹，完成后生效。
7. **大文件夹**：勾选 Jira（3458 封）后，受窗口/上限约束分批同步，不阻塞收件箱主同步。
8. **门控**：AppleScript 后端下该功能整体禁用且提示清晰。

## 9. 设计稿需求（给设计师）

需要输出设计稿的界面：

1. **Settings → 同步 Tab → 文件夹选择器**：动态文件夹列表（勾选框 + 名称 + 邮件数 + 同步状态）、刷新按钮、同步窗口设置、空态、davmail 门控态。
2. **Onboarding 文件夹选择步骤**：文件夹多选卡片/列表、系统文件夹锁定态、大文件夹提示、可跳过、与现有 onboarding 步骤视觉一致。
3. **Sidebar MAILBOXES 段扩展**：自定义文件夹行（图标 + 名 + 计数）、多文件夹时的折叠/展开、选中态、与现有收件箱/存档行一致。
4. **（可选）文件夹邮件列表头部**：标识当前在某自定义文件夹的上下文（面包屑/标题）。

**设计约束**：复用现有设计系统（coral 强调色、ink 色板、`NavRow`/`Section`/`EnvField` 既有组件语言）；Sidebar 严守「三个 section header」铁律，自定义文件夹挂在 MAILBOXES 段内。
