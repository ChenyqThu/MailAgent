# 多文件夹同步 PRD（Multi-Folder Sync）

> 让用户自主勾选并同步 Exchange 邮箱里的多个自定义文件夹，使这些文件夹的邮件享受与收件箱完全一致的能力（AI 分类 / Notion 同步 / 通知 / 线程 / 搜索 / 全套读写），并支持文件夹管理与嵌套层级呈现。
>
> **状态**：✅ **已实现**（P1-P6 全部落地，2026-06-09；davmail 多文件夹取数 + 完整 pipeline + L2/L3 gate + 写操作泛化 + 文件夹 CRUD + onboarding + 旧 folder_sync 展示链路清理；实现语义见 [`architecture-internals.md`「多文件夹同步」](./claude/architecture-internals.md)）
> **关联**：[技术设计](./multi-folder-sync-design.md) · [实现 handoff](./multi-folder-sync-handoff.md) · [设计 handoff](./multi-folder-sync-design-handoff.md)
> **决策基线**：完整 pipeline · 完整写操作 · 白名单手动勾选 · davmail-only · **文件夹管理 + 嵌套层级（davmail 支持前提）** · **统一接管并废弃旧 folder_sync 展示链路**（见 §7）
> **最后更新**：2026-06-09

## 1. 需求背景

### 1.1 现状

MailAgent 当前只同步两个**写死**的文件夹：**收件箱**（IMAP `INBOX`）+ **发件箱**（`Sent Items`，仅当 `SYNC_MAILBOXES` 含「发件箱」）。davmail 取数主循环 `get_new_emails()` 把同步目标硬编码成这两个，其它文件夹名被静默忽略。

### 1.2 痛点

公司 Exchange 用户普遍用 **Outlook 规则**把邮件自动分流到自定义文件夹。**实测该用户邮箱有 18 个文件夹**，大量有价值的邮件落在自定义文件夹里：

| 文件夹 | 邮件量（实测） | 性质 |
|---|---|---|
| Jira | 3458 | 项目协作通知 |
| DMS固件发布 | 728 | 研发发布通知 |
| Notion | 381 | 协作平台通知 |
| Bugzilla / Confluence / Figma | — | 工具链通知 |
| 待办 / 必要文档路径 / 对话历史记录 | 0~少量 | 个人归类 |

这些文件夹的邮件目前**完全在 MailAgent 视野之外**：看不到、不分类、不进 Notion、不通知。用户仍需切回 Outlook 查看——违背「统一邮件中枢」定位。

**更隐蔽的副作用 —— 收件箱状态漂移**：Outlook 规则通常「邮件先投递到收件箱(INBOX)，规则再移走到文件夹」。MailAgent 秒级轮询 INBOX，常**抢在规则移走前抓到**邮件、以 `mailbox=收件箱` 入库；之后 Outlook 把它移到目标文件夹，但 MailAgent 不跟踪移动，记录**定格在抓取那一刻**。后果：① 你在收件箱看到的部分「类通知」邮件，真实 Outlook 里早被移到文件夹（**收件箱被污染**）；② 只有 INBOX 窗口期「漏网」的才进来，服务器端规则直投/错过窗口的完全缺失。本功能落地后这些邮件**按真实所属文件夹正确归类**，同时消除漂移。

### 1.3 可行性（已实测验证）

davmail（EWS↔IMAP 桥）已被实测证明具备能力：
- **列得出**：`LIST "" "*"` 返回全部 18 个文件夹，含自定义文件夹，中文名经 modified-UTF7 解码可读；hierarchy delimiter 为 `"/"`（**支持嵌套层级表示**）。
- **进得去、取得到**：自定义文件夹 `SELECT` + `UID SEARCH` 成功取邮件（Jira 3458 / Notion 381 / DMS固件发布 728 均验证）。
- **有增量游标**：每文件夹独立 `UIDVALIDITY` / `UIDNEXT`。
- **管理能力（协议层）**：文件夹增删改 = IMAP 标准 `CREATE`/`DELETE`/`RENAME`，davmail 映射为 EWS 文件夹操作（⚠️ 实现时需实测确认映射边界 + 系统文件夹保护）。

### 1.4 旧 folder_sync 展示链路实测发现（强化「接管」理由）

打包应用里**已有**一个「存档/草稿箱」展示功能（旧 `folder_sync` 模块），但**实测发现它从未真正工作**：配置全开（davmail + `MAILBOX_FOLDER_SYNC_ENABLED=true` + 前端入口 `true`）、主同步活跃（收件箱 8432 封 davmail 邮件、刷新到当天），但 `folder_sync_state` 表**零记录**（FolderSyncWorker 从未启动一次 tick）、`folder_email` 表 **0 行**。即一个「装了门面没接管线」的半成品。

→ 这印证两点：① 旧 folder_sync 价值有限且从未端到端验证；② 本功能应**统一接管所有文件夹**（含存档/草稿箱），走已验证在跑的主链路，并**分阶段废弃**旧展示链路（详见 §7 D7 + 技术设计附录 B）。

## 2. 目标与非目标

### 2.1 目标

1. **文件夹发现**：用户能看到自己 Exchange 邮箱里所有可同步文件夹（含嵌套层级结构）。
2. **白名单勾选**：自主勾选要同步哪些文件夹（默认一个不选，避免大文件夹无脑灌入）。
3. **完整能力对齐**：勾选的文件夹，其邮件享受与收件箱一致的全套能力——AI 分类、Notion 同步、通知、线程、全文搜索、附件，以及标旗/已读/归档/移动/回复/转发等全套读写。
4. **主菜单栏呈现**：左侧 Sidebar 动态呈现已勾选文件夹（**支持嵌套层级树**），点击查看该文件夹邮件。
5. **Onboarding 集成**：新用户 onboarding 加入「勾选要同步的文件夹」环节。
6. **文件夹管理**（davmail 支持前提）：在 App 内**创建 / 重命名 / 删除**文件夹，变更回写 Exchange，并对系统文件夹做保护 gate。
7. **嵌套子文件夹层级树**（davmail 支持前提）：发现、勾选、呈现都支持父子层级（`parent/child`），而非平铺。
8. **统一接管存档/草稿箱**：废弃旧 folder_sync 展示链路，存档/草稿箱并入本功能白名单走主链路。

> 目标 6/7 带「davmail 支持前提」——实现首步（P1）须实测确认 davmail 的写操作 EWS 映射 + 嵌套实际暴露；若某点 davmail 不支持，则该子项降级为「只读/平铺」并在文档记录。

### 2.2 非目标（首期不做）

| 不做 | 原因 |
|---|---|
| AppleScript 后端支持 | davmail-only；AppleScript 对中文文件夹名有匹配坑，作未来扩展 |
| 共享邮箱 / 委托邮箱 / 在线存档（In-place Archive） | davmail 普通 IMAP 不暴露；超出范围 |
| 文件夹的**移动/拖拽重组**层级（把 A 拖进 B 做子文件夹） | 首期管理只做创建/重命名/删除；拖拽重组作后续 |

### 2.3 产品定位与呈现边界（balance）

**核心张力**：把所有文件夹同步过来、还能管理层级 → 越来越像**完整邮件客户端**；但 MailAgent 定位是**重要邮件的 AI Agent**（AI 处理是核心价值）。更多呈现 = 更完整，但也可能信息过载、稀释 AI 价值、撑爆 Notion/LLM（Jira 3458 封自动通知若全量 AI 分类，成本高、价值低）。

**解法 —— 分层，"看得全" 与 "AI 聚焦" 解耦**。把一封邮件的待遇拆成三层，每个文件夹可落在不同层：

| 层 | 含义 | 默认策略 |
|---|---|---|
| **L1 查看层** | 同步进来 + 列表/详情/搜索/线程 + 管理 | 勾选的文件夹**都享受**（完整查看体验，成本低） |
| **L2 AI 层** | LLM 分类 / 优先级 | 收件箱全开；自定义文件夹**默认开但可逐个关**（自动化通知类建议关，省成本去噪） |
| **L3 推送层** | 飞书通知 / Notion 归档 | 收件箱按策略；自定义文件夹**默认关**，逐个可开 |

**原则**：**查看与管理可以完整**（满足"不漏邮件、不切 Outlook"），但 **AI/推送保持聚焦可控**（守住 Agent 定位，避免噪音淹没）。这细化（而非推翻）D1 的"完整 pipeline"——**能力完整，默认聚焦，用户可控**。L2/L3 的默认值与 per-folder 开关为「待产品定调」项（§7）。

## 3. 用户故事

- **US-1**：作为研发，我希望 Jira / DMS固件发布 的邮件也能被同步查看、必要时 AI 分类，不漏项目关键变更。
- **US-2**：新用户希望 onboarding 时就看到邮箱有哪些文件夹（含层级）并勾选要同步的。
- **US-3**：日常希望在左侧菜单直接点开「Notion」文件夹看邮件，不用切 Outlook。
- **US-4**：重度用户希望自定义文件夹里也能回复/转发/归档，体验和收件箱一致。
- **US-5**：谨慎的用户希望默认不要把 3458 封 Jira 一股脑灌进来，自己决定同步哪些、什么窗口。
- **US-6**：希望在 App 里直接**新建/重命名/删除**文件夹，不必切回 Outlook 管理。
- **US-7**：我的文件夹有父子层级（如 `项目/2026/Q2`），希望 App 里也按**树形**呈现，而不是一堆平铺名字。

## 4. 功能需求

### 4.1 文件夹发现（Folder Discovery）

- 后端拉取当前账户**可同步文件夹列表**（davmail IMAP LIST），**含层级结构**（解析 hierarchy delimiter `/` 还原父子关系）。
- 列表项含：显示名（解码后）、邮件总数、是否已勾选、是否系统文件夹、**父路径/层级**、是否有子文件夹。
- 系统文件夹（收件箱/发件箱）默认已同步、不可取消。
- 可刷新（Outlook 新建文件夹后重新拉取）。

**验收**：配置页「刷新」能看到 18 个文件夹、中文名正确、带邮件数；若有嵌套则按树呈现。

### 4.2 配置页（Settings → 同步 Tab）

在现有「同步」Tab 重构出**文件夹选择器**（取代旧的「存档/草稿箱」开关区）：

- **文件夹树/列表**：可勾选，**支持层级缩进展开**。每行：勾选框 + 文件夹名 + 邮件数 + 同步状态。父文件夹勾选可选「含子文件夹」。
- **文件夹管理操作**（davmail 支持前提）：行内/右键菜单提供**新建子文件夹 / 重命名 / 删除**；系统文件夹禁用这些操作（gate）。删除/重命名需二次确认（影响真实 Exchange）。
- **同步窗口控制**：首次同步窗口（最近 N 天）+ 单文件夹上限（最多 N 封）。
- **（可选）per-folder 处理开关**：L2 AI / L3 推送 的逐文件夹开关（见 §2.3，视产品定调）。
- **保存即生效**：写配置，后端按白名单增量同步（restart=yes 范式）。
- **空态**：未发现自定义文件夹时引导文案。
- **门控**：仅 davmail 可用；AppleScript 模式禁用并提示。

### 4.3 Onboarding 流程优化

在现有 onboarding（约 7 步）**邮箱配置后、完成前**插入「选择要同步的文件夹」步：
- 仅 davmail 显示；拉取文件夹列表（**树形**）→ 多选勾选 → 「可稍后在设置改」。
- 系统文件夹默认勾选+锁定；自定义默认全不选（白名单）。
- 大文件夹（>1000 封）轻量提示「首次同步可能较慢」。
- **可跳过**（= 当前行为，只同步收件箱/发件箱）。

### 4.4 主菜单栏（Sidebar）文件夹呈现

在 Sidebar 的 **MAILBOXES 段**动态追加已勾选文件夹：
- 复用 `NavRow` + `CountRight`；统一「文件夹」图标。
- **嵌套层级树**：父子文件夹按**缩进 + 展开/收起**呈现（而非平铺）。
- **🔴 约束**：受 §2.11「只能三个 section header」铁律——文件夹**挂在 MAILBOXES 段内**，不新增 header。
- 文件夹多/深时用「展开更多 / 折叠」控件避免过长。
- 点击 → 邮件列表按该 folder 过滤（复用现有虚拟化/缓存）。
- 计数走现有 SSE invalidate + 轮询兜底。

### 4.5 邮件能力（完整 pipeline 对齐）

自定义文件夹邮件在功能表现上与收件箱一致：列表/详情/附件、AI 分类（L2）、Notion 同步（L3）、通知（L3）、线程、FTS 搜索、标已读、标旗/归档/移动/回复/转发。

**关键**：写操作统一走 outbox SSoT + FanoutWorker；归档/移动从「写死 INBOX→Archive」**泛化为任意源→任意目标文件夹**。L2/L3 默认值见 §2.3。

### 4.6 文件夹管理（创建 / 重命名 / 删除）

> davmail 支持前提（P1 实测确认 EWS 映射）。

- **创建**：在某父文件夹下新建子文件夹（IMAP `CREATE`）。新建后出现在树里，可勾选同步。
- **重命名**：改文件夹显示名（IMAP `RENAME`）。同步过的本地邮件 `mailbox` 字段随之更新。
- **删除**：删文件夹（IMAP `DELETE`）。需二次确认 + 说明「同时删除本地已同步副本」。
- **系统文件夹保护**：收件箱/发件箱/Drafts/Sent/Junk/Trash 等**禁止**重命名/删除（gate + 灰态）。
- **一致性**：管理操作走 outbox SSoT（与其它写操作一致），失败有反馈。

### 4.7 嵌套子文件夹层级树

> davmail 支持前提（P1 实测确认嵌套实际暴露 + 中文层级名）。

- **发现**：LIST 解析 delimiter `/`，把 `parent/child/grandchild` 还原成树。
- **呈现**：配置页 + Sidebar + onboarding 都按树形（缩进 + 展开/收起）。
- **勾选语义**：勾父文件夹可选「仅本级」或「含全部子文件夹」。
- **降级**：若实测 davmail 不暴露嵌套（你当前都是顶层），自动退化为平铺，不阻塞主功能。

## 5. 交互流程

```
首次：账户配置 → 邮箱多选 → 【新】拉取文件夹树 → 勾选要同步的 → 权限/完成 → 启动同步
管理：Settings → 同步 Tab → 刷新树 → 勾选/取消 + 新建/重命名/删除 + 窗口设置 → 保存 → 按白名单增量同步
日常：Sidebar MAILBOXES 段 → 展开层级 → 点「Jira」→ 列表按 folder 过滤 → 查看/AI/回复/归档/移动
```

## 6. 边界与降级

- **6.1 大文件夹**：窗口（最近 N 天）+ 上限（最多 N 封）双约束分批拉，默认保守（90 天 / 2000 封，可调）。
- **6.2 davmail-only**：AppleScript 下文件夹发现/选择/同步/管理整体禁用并提示。
- **6.3 取消勾选**：默认保留本地邮件 + Notion 页，提供「同时清理」选项（待定）。
- **6.4 通知/AI 降噪**：见 §2.3 —— 自定义文件夹默认 L1 查看，L2 AI / L3 推送逐个可控、默认保守。
- **6.5 文件夹管理失败**：davmail 写操作失败（权限/系统文件夹/网络）须有清晰反馈，本地树回滚到服务器真实状态。
- **6.6 合规约束**：davmail PoC（well-known client_id 伪装）不可上生产；EWS 2026-10-01 退役，长期迁 Graph。

## 8. 验收标准（产品侧）

1. **发现**：davmail 用户在设置页拉取看到全部文件夹（含中文名 + 邮件数 + 层级）。
2. **勾选**：勾选 N 个保存后开始同步；取消后停止同步新邮件。
3. **完整能力**：新邮件被（按 L2 设置）AI 分类、（按 L3）同步 Notion、进 FTS 搜索、正确归线程。
4. **Sidebar**：已同步文件夹按层级呈现、计数正确、点击过滤正确。
5. **写操作**：自定义文件夹内标旗/已读/归档/移动/回复/转发正确双向同步。
6. **文件夹管理**：创建/重命名/删除生效并回写 Exchange；系统文件夹被保护。
7. **Onboarding**：新用户能勾选文件夹（树形），完成后生效。
8. **大文件夹**：勾选 Jira（3458 封）受窗口/上限约束分批，不阻塞收件箱主同步。
9. **门控/降级**：AppleScript 后端整体禁用；davmail 不支持的管理/嵌套子项优雅降级。
10. **接管**：存档/草稿箱通过新链路可见（旧 FolderSyncWorker 不再被依赖）。

## 9. 设计稿需求（给设计师）

需出稿界面：

1. **Settings → 同步 Tab → 文件夹选择器**：动态文件夹**树**（勾选框 + 名称 + 邮件数 + 层级缩进 + 展开/收起 + 同步状态）、刷新、**文件夹管理操作**（新建子文件夹/重命名/删除，系统文件夹禁用态 + 删除二次确认弹窗）、同步窗口设置、（可选）per-folder L2/L3 开关、空态、davmail 门控态。
2. **Onboarding 文件夹选择步骤**：文件夹**树形**多选、系统文件夹锁定态、大文件夹提示、可跳过、与现有 onboarding 视觉一致。
3. **Sidebar MAILBOXES 段扩展**：自定义文件夹行（图标 + 名 + 计数）、**嵌套层级（缩进 + 展开/收起）**、多文件夹折叠、选中态、收起态（56px）下的呈现。
