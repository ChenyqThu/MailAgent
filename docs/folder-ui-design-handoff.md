# Handoff — MailAgent 存档/草稿箱 UI 设计

> 给 claude design 的任务 brief。可直接粘贴对话使用；详细需求见**附件 PRD**（`folder-ui-prd.md`）。

## 任务

为 **MailAgent**（macOS 邮件桌面客户端，Electron + React + Tailwind）设计两个新邮箱入口的界面：
**存档 (Archive)** 和 **草稿箱 (Drafts)**。这是已上线 app 的新增视图，需与现有界面无缝融为一体。

完整功能 / 数据 / 交互 / 设计系统约束都在**附件 PRD**（`folder-ui-prd.md`），请先通读。

## 请连同 PRD 一起参考的现有设计稿（同仓 `frontend/ref/`，作为风格基准）

| 文件 | 用途 |
|---|---|
| `mockup-inbox.html` | **最重要** — 收件箱列表 + 详情的视觉基准，含真实 ink token CSS。新界面必须延续它 |
| `mockup-compose.html` | **撰写器基准** — 草稿新建/编辑的撰写器请沿用这套撰写界面语汇，别另起炉灶 |
| `mockup-detail-window.html` | 邮件详情呈现参考 |
| `icon-spec.html` | 图标规范（lucide 线性图标体系） |

> 这些 mockup 里的配色变量、字号 class、毛玻璃面板、间距就是设计系统的事实标准，请直接复用其 CSS token，不要发明新的。

## 最重要的三件事

1. **视觉与收件箱高度一致** — 同一个 app 的新视图。严格沿用 `mockup-inbox.html` 的 ink token 配色、`glass` 毛玻璃面板、字号体系（text-micro/meta/aux/body/lead/subj）、两栏布局（列表列 + 详情列，左侧已有 Sidebar）、列表行 / 详情头 / 48px toolbar 的视觉语汇。

2. **抓住差异化机会 —— 更干净**：存档/草稿**没有 AI 信息条、没有线程折叠**（见 PRD §4）。收件箱列表行信息很密（发件人 + 主题 + 摘要 + AI 优先级点 + 分类 + 动作 chip）；存档/草稿可以去掉这层 AI 噪音，**重新平衡信息层次、增加留白**。不要简单"删掉 AI 行了事"，而是为这两个更轻的场景做更舒展的版面。

3. **撰写器是体验重点**：草稿撰写器 = 收件人/抄送/主题 输入 + **富文本正文**（加粗/斜体/下划线/删除线/有序·无序列表/链接/行内代码）+ 格式工具栏。工具栏必须融入设计系统（参考 `mockup-compose.html`），不要是通用富文本框那种突兀的灰色按钮条。

## 必须遵循（不可改）

- 设计系统 token / 字号 / 组件库（Radix + lucide），见 PRD §2 + 上述 mockup
- 数据字段边界（PRD §4）：只用列出的字段；**不要设计依赖不存在的数据**，尤其不要加 AI 优先级/分类/摘要
- 功能与交互（PRD §3/§5）：存档 = 看 / 移回收件箱 / 永久删除；草稿 = 看 / 新建 / 编辑 / 发送 / 删除；移回·删除·发送都要二次确认弹窗
- 两栏布局基底，左接现有 Sidebar（MAILBOXES 段新增「存档」「草稿箱」两入口）

## 可以自由发挥

- 列表行的信息层次、密度、视觉权重（这是改进重点）
- 详情页留白与元数据呈现方式
- 撰写器版面与工具栏布局
- 空态 / 加载态 / 错误态的精致度（**空态不要显示裸 "0"** —— 这是当前实现的 bug）
- 操作按钮视觉权重 + 三个确认弹窗的样式

## 交付物

mockup HTML（含真实 ink token CSS，与 `mockup-*.html` 同风格、可独立浏览器打开），覆盖以下屏 × 态：

1. **存档** — 列表（有数据 + 空态）+ 选中某封的详情
2. **草稿箱** — 列表（有数据 + 空态）+ 详情
3. **撰写器** — 新建（空白）+ 编辑（载入已有草稿）
4. **三个确认弹窗** — 移回收件箱 / 永久删除 / 发送（发送措辞强调"真实发出"）
5. **加载态 + 错误态**

请在稿中标注用到的 token / 字号 class / 间距，方便工程 1:1 还原。

## 背景（可选）

- 单用户 dogfood 的高频邮件工具，重信息密度 + 操作效率 + 视觉精致度。
- 后端数据已就绪（DavMail IMAP → 本地 SQLite），工程拿到 mockup 后**只重写 UI 层组件**，数据接线不变 —— 所以你可以放手重新设计视觉，不必担心后端约束（只要不超出 PRD §4 的字段边界）。
- 已有一版工程实现但视觉不满意（PRD §8 列了现状 + 可改进方向），欢迎完全重新设计。
