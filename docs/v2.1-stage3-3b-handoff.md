## 2. 关键设计输入 / 决策（动手前吃透）

- **D1 持久化 cadence 由 platform 控**：harness 每 chunk 调 `platform.persist.streamContent`（fire-and-forget void）。electron = 同步 `updateMessage`（零回归）；http = debounce ~1/s 合并 PATCH，`finalizeMessage` **先 flush 该 msg 待发增量再写终态**（防终态被旧增量覆盖；harness 所有终态 patch 已带 `content=buffer` 做双保险，steps3-4 review MEDIUM-2）。
- **D2 custom-api 解析留 shared / notion-agent 复刻 Python**：按后端性质分（HTTP 可代理/浏览器解析 vs 子进程必服务端）。两者各自单实现 → 零 parity。
- **D3 3b 不搬执行进 renderer**（那是 3c）。3b 只做后端端点 + HttpChatPlatform impl，electron 路径继续零回归。
- **D4 notion-agent 也走 harness**（empty tools 首轮 `collected.length===0` 即 end_turn = 等价单遍）。**注意**：3a 为零回归**保留了 dispatcher legacy 单遍**（notion-agent 当前走 legacy）；D4「删 legacy 单遍」推迟到 3c（设计 §4 D4 + handoff 历史标注 D4 删 legacy 3c）。3b 不强制删 legacy。
- **D5 本地也走 serve-api**：3c cutover 后本地 renderer 也经 serve-api。3b 的 ElectronChatPlatform 仍是过渡（直调保零回归）。
