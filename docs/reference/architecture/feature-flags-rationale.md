| `MAILAGENT_INBOUND_READ_RECONCILE_ENABLED` | `false` | 入向「未读→已读」单向回收（davmail-only，issue #58）：外部客户端（Outlook/OWA）标已读后把本地未读收敛为已读。**只做未读→已读单向**（已读→未读 / flagged 不碰）、**只收件箱**、**恒走 outbox→notion**（绝不直调 Notion——Sprint15 死循环根因）。🔴 **判定分两步：`UID SEARCH UNSEEN` 只出候选，提交前对候选 uid 定向 `UID FETCH (UID FLAGS)` 复核才是判据**——「不在 UNSEEN 集」有三种成因且在 SEARCH 结果里长得一样：被外部标已读 / 已归档·删除·被规则搬出 INBOX（**仍未读**）/ 窗口内 UID 空洞；只凭缺席就写库 有**未终态**（pending/processing/failed）flag_sync intent → 本轮跳过（避 fanout 窗口误判；只认 pending 会漏掉正在派发/退避重试的在途 intent）；(b) `mailapp_payload=None`（服务器是已读真源，不回写 Mail.app）；(c) 本地 imap_uidvalidity ≠ 服务器 UIDVALIDITY 的行整批跳过（uid 全失效防误判）；(c2) 🔴 **截断窗口下界闸**——`davmail.folderSizeLimit`（>10k 邮箱必配）让 IMAP 视图只剩最近 N 封，窗口外老邮件在 UNSEEN 里必然缺席，**缺席 ≠ 已读**；故 SELECT 后按序号 FETCH 视图最老 UID 当下界，只判 `imap_uid >= 下界` 的行（少了它会把真未读老邮件批量误标已读）；(d) 🔴 **提交原子性**——「(a) 在途 intent 复核 + `WHERE is_read=0` 的 CAS 置已读 + notion 入队」在**同一个 `BEGIN IMMEDIATE` 事务**内（`src/sync/outbox_intents.py::converge_local_read_atomic`，两表同库故一个连接盖得住）：分开提交时 ① 入队失败会留下「本地已读但 Notion intent 永久缺失」（下轮只查未读行，该封再不进候选）② 闸与写之间的 TOCTOU 会把用户刚点的「标为未读」吞掉（json_patch 合并覆盖）。🔴 **收敛必须在工作线程**——`converge_local_read_atomic` 是同步 SQLite 事务，锁**等待**若发生在 event loop 线程上，别的进程持写锁时每封候选都能把整个 watcher（fanout / reverse / island 全部 worker 的 tick）冻住；故整块 `asyncio.to_thread` 出去（本地未读集查询同理），且传**短** busy timeout（`READ_RECONCILE_LOCK_TIMEOUT_SEC=2s`，远低于 outbox 默认 30s——收敛是可跳过的便利型写，下轮必重判）；超时抛 `ConvergeLockBusy` 保守让路，且**第一次锁超时就终止本轮**（不是"连续 N 次"——锁超时与成功交替出现时"连续"计数永远清零，chunk 里靠后的封会在前面几十次 × 2s 的锁等待之后才提交，把下面那个残留竞态窗口撑到近百秒）；已提交的前序封不回滚，被跳过的封下个周期重新 FETCH 复核重判（收敛幂等，不丢状态）。另有**累计耗时预算**（`READ_RECONCILE_CHUNK_BUDGET_SEC=3s`）兜住另一形态：别的 writer 在每封之间反复抢放锁时，每封都在 timeout **之前**拿到锁 → 每封都成功、`ConvergeLockBusy` 一次都不抛，但 100 封 chunk 能累计到分钟级、seen_map 一样在变旧；故单 chunk 收敛累计超预算即同样终止本轮（`abort_reason` 分 `lock_timeout`/`time_budget`，warning 文案可辨）。取 3s 的依据=无竞争时整个 chunk 全是本地语句（100 封 × 个位数毫秒 ≈ 0.2-0.5s），留一个数量级余量不误伤正常路径。⚠️ **已知残留竞态（有意不消除，有测试固化）**：定向 FETCH 返回 `\Seen` 之后、本轮事务提交之前，用户在 Outlook 标回未读——此刻**尚无**任何本地写或 outbox intent，CAS 与在途闸都看不见 → 该封仍被收敛，且本功能单向、不自愈。处置=复核与提交按 chunk 紧邻（`READ_RECONCILE_CONVERGE_CHUNK=100`，把窗口从「整批候选处理时长」收窄到「单 chunk 内、该封之前那些收敛事务的累计时长」——无锁竞争时全是本地语句、毫秒级；一旦有一封等锁超时、或整个 chunk 的收敛累计超过 `READ_RECONCILE_CHUNK_BUDGET_SEC` 即终止本轮，既不让锁等待逐封累加撑大窗口，也不再消费已经变旧的 FETCH 快照；两道闸合起来把窗口钉在常数量级「预算 + 一次锁等待」≈5s，与候选量、chunk 长度都解耦），再窄一档要 CONDSTORE/MODSEQ（DavMail 经 EWS 桥支持存疑，且**写在本地**、TOCTOU 依旧只是窗口更小，并非闭合），真正闭合只有提交后补偿事务（撤销本地已读 + 覆盖可能已派发的 Notion intent，而「覆盖」正是 Sprint15 死循环那条出向路径，补偿本身又有自身竞态、代码量超过功能本体），对默认关的便利功能不成比例；用户侧兜底=再标一次未读。🔴 **绝不挂 5s radar poll**——独立低频周期（`MAILAGENT_INBOUND_READ_RECONCILE_INTERVAL_SEC` 默认 300s），radar 每轮只用轻量 STATUS，把 UID SEARCH UNSEEN 挂每轮会重现 EWS 全量枚举限流（issue #46）。收敛后整轮只发一条 `email.flag_changed`（`internal_id=None`，不按封刷屏），data 携带**有界** `internal_ids`（上限 `READ_RECONCILE_EVENT_ID_CAP=200`，超限 `ids_truncated=true` 让前端退化成失效所有活跃 detail）——不带 id 时只失效 main-list + `mailboxes`，打开中的邮件详情 toolbar 会一直显示未读。默认关（灰度）；false = 字节级 inert。AppleScript 模式不激活（缺 `fetch_inbox_seen_flags` 即整段不激活——没判据就不许猜）。详见 new_watcher `_reconcile_inbound_read` |
