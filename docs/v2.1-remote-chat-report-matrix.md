## 为什么需要这张表

V2.1 的风险 = 「某个能力只补了一半的层（serve-api 端点有、客户端没接 / 形状漂移 / 没测）」。靠人脑记必漏。
五招防漏：① 能力矩阵看板（本表）② schema 契约对齐 IPC 形状 ③ 删除驱动（删 main chat 直跑，编译器枚举调用点）④ 残留检测 ⑤ 每阶段 codex review + 验收 gate。

图例：✅ 完成 · 🟡 doing · ⬜ 待办 · ➖ 不适用

## 架构（B-pure-unified，零 parity）

harness 逻辑 `shared/chat/`（一份，renderer + browser 都跑）→ `httpPlatform`（一份）→ serve-api（一份后端，无 harness 逻辑）。本地 token 由 main `webRequest` 透明注入，对 harness 透明。详见 [plan](file://~/.claude/plans/twinkling-floating-puppy.md) + 最终架构文档 `docs/claude/remote-chat-report-architecture.md`（阶段 3 末产出）。
